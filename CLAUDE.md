# Траты — правила работы с проектом

Личное PWA для учёта расходов. Владелец — не разработчик: общаться **по-русски, простыми словами**, без жаргона (а если термин нужен — объяснить его). Делать всё «как принято», не дожидаясь, пока попросят.

## Что где

| Файл | Что внутри |
|---|---|
| `index.html` | Всё приложение: разметка, стили, JS (разделы пронумерованы в комментарии в начале `<script>`) |
| `sw.js` | Service worker: офлайн-кэш. `VERSION` управляет обновлением у пользователей |
| `manifest.json`, `icons/` | Установка на экран «Домой» |
| `inbox-worker/worker.js` | Сервер «Входящие» (Cloudflare Worker + KV) для трат из Apple Pay и SMS |
| `README.md` | Инструкция для пользователя |
| `CHANGELOG.md` | Журнал версий — пополнять при каждом изменении |

Сайт публикуется через **GitHub Pages из ветки `main`**: всё, что попало в `main`, через 1–2 минуты у пользователя на телефоне. Сборки нет — файлы отдаются как есть.

## Как вносить любое изменение

1. **Ветка.** Работать в отдельной ветке от свежего `main`, не коммитить в `main` напрямую.
2. **Не ломать данные.** Данные пользователя живут только в `localStorage` телефона (`traty.data.v1`), потерять их нельзя:
   - новые поля — только с значениями по умолчанию в `defaultState()` **и** в `migrate()` (старые данные должны открываться без ошибок);
   - не переименовывать и не удалять существующие поля; если формат правда нужно поменять — миграция в `migrate()` и предупреждение владельцу;
   - проверить, что импорт/экспорт JSON (`exportJSON`, `parseBackupJSON`, `handleImportFile`) и облачная копия (`Backup.snapshot`) учитывают новые данные.
   - данные: `expenses`, `incomes` (как покупки + `kind: 'income'`), `goals`, `debts`, `categories`, `templates`, `merchantRules`, `inbox`, `settings` (в т. ч. `inbox`, `backup`, `notify`), `meta`.
3. **Версия.** Поднять `APP_VERSION` в `index.html` и `VERSION` в `sw.js` (одинаково: `1.2.0` → `traty-v1.2.0`). Без этого у пользователя не появится «Доступна новая версия». Мелкое исправление — третья цифра, новая функция — вторая.
4. **Проверка перед слиянием.** Запустить локально (`python3 -m http.server 8000`) и прогнать в Playwright с эмуляцией iPhone: новая функция + основные старые сценарии (добавить покупку, шаблон, аналитика, импорт JSON). Смотреть скриншоты, светлую и тёмную тему, узкий экран (iPhone SE). Ошибки в консоли (`pageerror`) недопустимы.
5. **Документация.** Запись в `CHANGELOG.md`; если меняется то, что видит пользователь, — `README.md`.
6. **Коммит, push, pull request** с понятным описанием на русском: что сделано, как проверено, что не проверено.
7. **Слияние.** Изменения, которые только добавляют новое и проверены, можно сливать (владелец согласен). Если изменение трогает формат данных, удаляет что-то или рискованно — сначала объяснить владельцу и спросить; перед слиянием напомнить сделать «Экспорт JSON».
8. **После слияния** — сказать владельцу: открыть приложение и нажать «Обновить».

Если что-то не удалось проверить (например, работу на реальном iPhone) — прямо сказать об этом.

## Сервер «Входящие» (Cloudflare)

- Аккаунт Cloudflare владельца, воркер `traty-inbox`, адрес `https://traty-inbox.traty-758cef38.workers.dev` (он же `DEFAULT_INBOX_URL` в `index.html`), KV namespace `traty-inbox` (привязка `INBOX`), секрет `TOKEN` — ключ владельца.
- У каждого пользователя свой ключ и своя очередь (`tx:<id>:…`), ключи выдаёт `POST /register`.
- Менять API только **совместимо**: уже настроенные команды на iPhone (`POST /tx?key=…` с полями `amount`, `merchant`, `card`, `text`, `source`) должны продолжать работать.
- Секреты и переменные воркера: `TOKEN` (ключ владельца), `VAPID_PRIVATE_JWK` (секрет, ключ подписи уведомлений), `VAPID_PUBLIC`, `PUSH_SUBJECT` (адрес сервера). Расписание (cron) — `*/15 * * * *`: вечерние напоминания и итоги месяца. **Ключи VAPID нельзя менять** — иначе все подписки на уведомления перестанут работать; при обновлении кода сохранять привязки (`keep_bindings` в metadata загрузки скрипта) и после развёртывания проверить `GET /push/key`.
- Копии (`/backup`) зашифрованы в приложении; сервер не должен получать код восстановления.
- ИИ-помощник — отдельный воркер `traty-ai` (`traty-ai-worker/`, адрес `AI_URL` в `index.html`): Gemini, доступ по тем же личным ключам (привязки `INBOX`, `TOKEN`), ключ Google — секрет `GEMINI_API_KEY`. Пользователь ничего не настраивает: **никаких полей для ключей и адресов в интерфейсе**. При обновлении — `keep_bindings: ["secret_text", "kv_namespace"]`.
- Перед развёртыванием — проверить воркер локально с поддельным KV (шифрование уведомлений — расшифровкой библиотекой `http_ece`). Развёртывание — через Cloudflare API (`PUT /accounts/<id>/workers/scripts/traty-inbox`, metadata с привязками `INBOX` и `TOKEN`). Нужен API-токен: попросить владельца создать его (шаблон «Edit Cloudflare Workers») и передать через защищённую форму, **никогда через чат**. После работы напомнить удалить токен.
- После развёртывания проверить живой сервер (ключ владельца работает, неверный ключ → 401).

## Безопасность

- Никаких ключей, токенов и паролей в репозитории и в коммитах.
- Не просить владельца присылать секреты в чат.
